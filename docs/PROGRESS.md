## Standing findings

- Licensing (literature §6.9): PIG is for non-profit academic use; weights trained on it cannot ship without the maintainers' permission. Plan: Engine A (rules only) ships unconditionally; shipped learned weights come from permissive data (textbook oracle, Beringer corpus from pydactyl (MIT), Mutopia editorial fingerings after per-piece checks); PIG is evaluation-only. Asking the PIG maintainers for permission is the user's decision.
- Content licensing: five library engravings are CC BY-SA (Schumann Op. 68 No. 1 and No. 8, Moonlight mvt 1, Mozart K.545, Bach Invention 1); the compositions are public domain but the files require attribution in the app (typesetter, licence, Mutopia id are in `content/manifest.json`). Scarborough Fair uses the traditional Dorian tune.
- Literature leaderboard (PIG test, M_gen): human ceiling 71.4; ArGNN 66.84 (best published); HMM3 64.5; an unverified exact rule-based Viterbi (chirality project) 64.9. Nothing new on the benchmark since 2022.
- Baselines (`docs/research/baselines.md`, scorer verified against the official C++ evaluator on 1,478 pairs): test-split M_gen: FingerFlow with weights learned on 031-150 68.6 (best; beats FHMM3 by +3.6 with CI [+1.1, +6.3]), ArGNN beam 66.7, lumikey retrained 66.2, chirality exact Parncutt Viterbi learned 66.0 (uniform weights 65.4), Hand-thesia 65.8, FHMM3 65.0, pydactyl Jacobs 63.6 / Parncutt 62.9, CHMM 62.0. Lessons: exact search over Parncutt beats pruned search by +2.5; learned linear weights beat hand-tuned by +4.3; linear models generalise (train 70.3 vs test 68.6) while HMM and neural models overfit. Released lumikey and APF-Gen checkpoints are contaminated by the test pieces. Floors: M2 (rules only) should land at or above chirality-uniform 65.4; M3 target is to beat FingerFlow-learned 68.6 (69), stretch 71 (human 71.4).
- The recombination metric charges one point per annotator switch (Nakamura 2020 App. A); M1 Task 9 was corrected but implemented before the correction, so M2 Task 0 reconciles the TypeScript metrics with the Python reference.
- Rendering: Verovio keeps our note ids and tags every fingering digit with `data-startid`; one CSS class turns one note or digit red; cursor sync via `getOutputTimestamp()` is within 5 ms.
- Readability (`docs/research/readability.md`, 2026-10-14): teaching editions print 32 percent of notes, library pieces a median 18 percent; half as often on repeats. The spec's context triggers predict printing below chance; the binding reduction is now the greedy forward pass over the validated player model R0-R5 (semitone/2 steps, chord fill, repeat memory) plus first notes, pins and low confidence; density targets per level (floor 30/35/40 for levels 1-2/3/4-5, target 20/25/30, editor level 15/15/25) and never above the editor's density on the same piece. Verification spec 3.6 and the goals table carry the dated amendment; the M5 plan drafter was told.
- Learning prototype (`docs/research/learning-prototype.md`, 2026-10-14): Python port of the engine's features matches the TypeScript engine on all 36,099 fingers of 119 PIG train pieces. Averaged PA-I with Hamming augmentation (rho 1, C 0.2, epoch chosen on validation) gains +4.8 on PIG validation (69.5 vs rules 64.7; CV +6.8); transition indicators give most of it; extra feature families are noise. The open-data set (textbook + Beringer + Mutopia train) stays at rule level on PIG (64.9) but gains +9 on the Mutopia oracle (65.5 vs 56.6): the shipped set cannot reach FingerFlow's 68.6 without PIG-fitted weights (decision for the user: ask the PIG maintainers for permission). 28 percent of expert hand-annotations violate a solver hard rule, mostly legato overlaps of about 50 ms: first M3 Task 7 hypothesis. M3 plan corrected (binding section at its end).
- Teacher review (`docs/research/teacher-review.md`, 2026-10-14): a blinded Opus reviewer finds 99 percent of planted faults within one note, 2.5 objections per 100 notes on expert fingerings, expert > corrupted 80/80, flags disputed notes 3x more than unanimous ones, self-consistency 0.95; about 16k tokens and 72 s per passage. Adopted as verification spec 3.12: a weekly job beside pnpm verify (lowest-confidence passages, hard-error gallery entries, library controls, user edits) that turns shared objections into lab-notebook hypotheses; never a gate. Wiring is M7 work; two fixes first (legend: dur is sounding length; composer-hidden control).
- Hand separation (M6, 2026-10-14): the shipped tables in packages/engine/src/io/midi/params/hand-motion.json come from the library and the Mutopia train half only; PIG-derived hand statistics stay research-only (research/weights/hand-motion-pig.json) and score 91.76 against the shipped 92.05 on PIG test. Pooled counts let the larger Mutopia corpus dominate and mis-split Twinkle; equal weight per corpus fixed it.
