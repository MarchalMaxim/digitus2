# M4 App MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A usable web app: a welcoming library of the 30 built-in pieces, a score view that shows the engine's finger numbers on every note, playback with a sampled piano, a red cursor and an on-screen keyboard that shows which finger plays which key, export of the fingered MusicXML, an about page with every attribution, and the application half of the verification loop (Playwright flows, the one-red-element check, axe, visual baselines, a bundle budget) wired into `pnpm verify` and CI.

**Architecture:** `apps/web` is a Vite + React 19 app (`@digitus2/web`) that consumes `@digitus2/engine` through two Web Workers: an engine worker (parse, solve, inject fingerings) and a Verovio worker (layout to SVG). The main thread only swaps classes and patches digit text. A zustand store holds the view, the open piece and persisted settings; the URL hash mirrors the view. Audio is smplr's `SplendidGrandPiano` driven by our own look-ahead transport, with the cursor clocked by `AudioContext.getOutputTimestamp()`. The design system is a handful of CSS custom properties; the single red is one class, `.is-red`, and a script plus an end-to-end helper enforce it.

**Tech Stack:** TypeScript strict, React 19.3, Vite 8, zustand 5.0.15, verovio 6.3.0, smplr 1.1.0, vitest 3 + happy-dom + Testing Library, @playwright/test 1.59.1 (matches the Chromium 1217 build already installed on this machine), @axe-core/playwright. No router, no CSS framework, no animation library (rendering spike section 7).

**Spec:** `docs/superpowers/specs/2026-10-13-digitus2-design.md` (sections 4, 5, 9, 11) and `docs/superpowers/specs/2026-10-13-verification-design.md` (goals table rows "Be fast" and "Honor the design brief", checks 3.9 and 3.10). Binding technology decisions and the measured snippets: `docs/research/rendering-spike.md` (sections 1, 7, 8, 9). Library data: `docs/research/content-library.md` ("Licensing notes", "Notes for the app") and `content/manifest.json`.

## Global Constraints

- Black `#000000`, white `#ffffff`, a small gray scale, and exactly one red `#e3000f`, used by exactly one CSS class (`.is-red`). No other chromatic color anywhere in `apps/web` (spec section 9; `scripts/check-colors.mjs` enforces it).
- Exactly one red element on screen in every state (spec section 9; definition in "The red element rule" below; `e2e/helpers/red.ts` enforces it in every Playwright state).
- Motion: 120 to 200 ms ease-out transitions, no bounce; `prefers-reduced-motion` turns durations to 0 (spec section 9). The cursor never animates: a class swap in the `requestAnimationFrame` callback (spike section 7).
- Layout works from 360 px wide up (spec section 9; the `mobile` Playwright project runs at 360 x 740).
- Largest contentful paint under 2 s on the library page; zero serious or critical axe violations on every page (verification spec goals table).
- Initial JavaScript for the library page at most 150 KB gzip; Verovio (2.3 MB gzip) is a lazy chunk never statically imported by the entry (spike section 9).
- The app depends only on the engine's public API (`@digitus2/engine`), never on its internals (spec section 4). Parsing, solving and layout run in workers; the main thread never parses MusicXML or runs the solver.
- No network calls except static assets and piano samples (spec section 9). Playwright runs use a silent instrument (`?audio=silent`) so tests need no network and no sound device.
- Repeats are not expanded by the engine reader yet: playback follows document order. MIDI files are refused with a friendly notice (MIDI import is milestone M6). Fingering edits, pins, explanations and the readability reduction are milestone M5.
- `pnpm verify` must stay green after every task; implementers do not run git (CLAUDE.md). Nothing is written under `packages/engine/**` in this plan: the engine is consumed as is. If an engine export named below is missing or differently named, read `packages/engine/src/index.ts` and use the actual name; do not edit the engine.
- Windows host: long commands run in the background; the Write tool for long files (CLAUDE.md).

## Review Focus

1. A dropped `.mxl` archive, a UTF-16 MusicXML export, or a file that is not MusicXML at all must open or show a readable error with a way back, never a blank score or a hung "Preparing" state. Pinned by Task 6 (`shows an error state with a way back when the file is not a score`) and Task 3 (`refuses a MIDI file with a notice`).
2. Opening a long piece (Mozart K.545, 1288 notes) must keep the page responsive: the status line must paint before solving starts, and the whole open must finish in bounded time. Pinned by Task 6 end-to-end test (`opens K.545: status appears first, score within 8 s`).
3. The cursor must be in sync with what the listener hears on devices with output latency (Bluetooth adds 150 to 250 ms). Pinned by Task 7 (`audibleTime uses getOutputTimestamp when available and falls back to currentTime`).
4. Resizing the window during or after rendering must never duplicate pages or show a stale layout: a render result that belongs to an older request is dropped. Pinned by Task 5 (`drops results of superseded render requests`) and Task 6 (`re-renders once when the width bucket changes`).
5. Settings saved by an older version of the app must not break a newer one: missing fields fall back to defaults and unknown fields are ignored. Pinned by Task 2 (`merges a partial stored settings object with the defaults`).

## Engine API consumed (names as exported by `packages/engine/src/index.ts` after M1 and M2)

```ts

  parseMusicXml, // (input: string | Uint8Array, opts?: { source?: string }) => { score: Score; editorial: Assignment; warnings: string[] }

  injectFingerings, // (xml: string | Uint8Array, score: Score, assignment: Assignment, opts?: { replace?: boolean }) => string

} from '@digitus2/engine';
```

`Note` fields used by the app: `id`, `onsetTick`, `offsetTick`, `onsetSec`, `offsetSec`, `midi`, `hand`, `measureIndex`, `isGrace`, `chordId`, `sourceIndices`. `Score` fields: `meta`, `divisions`, `tempoMap`, `timeSignatures`, `measures`, `notes`. Fixture facts the tests rely on (measured with `digitus2 inspect`): `apps/web/fixtures/short-piano.musicxml` has 67 sounding notes (41 right, 26 left), 8 measures, 20.0 s at 96 qpm, and 67 editorial fingerings; `content/scores/twinkle-twinkle-little-star.musicxml` has 64 notes (42 right, 22 left), 12 measures, 28.8 s at 100 qpm; `content/scores/mozart-sonata-k545-mvt1.musicxml` has 1288 notes and 73 measures.

## The red element rule (the definition every test uses)

- A **red root** is a visible element (not `display: none`, `visibility: hidden` or `opacity: 0`, and not inside such an element) whose own computed `color`, `background-color`, `border-*-color`, `outline-color`, `fill` or `stroke` equals `rgb(227, 0, 15)`, and whose ancestors are not red roots. Descendants of a red root are not inspected (a white label on a red button is one red root).
- A state passes when there is exactly one red root, **or** when every red root is an SVG `g.note` or `g.chord` inside `.score-sheet` and all of them carry the same `data-onset-tick` value (the playback cursor lights every note that starts at that instant, in both hands; that is one cursor).
- Which element is red, by state: library: the "Start with …" button. Score, stopped or paused: the Play button. Score, playing: the cursor notes. About: the "Back to the library" button. Error states: the "Back to the library" button. The drop zone, the notice, hover and focus states, pressed keys and finger digits are never red.

```ts
export function prefersReducedMotion(): boolean {
  return (
    typeof window !== 'undefined' && window.matchMedia('(prefers-reduced-motion: reduce)').matches
  );
}

/** One-shot fade-in used when a digit changes after a re-solve. Never used for the cursor. */
export function flash(el: Element): void {
  if (prefersReducedMotion()) return;
  const animate = (el as Element & { animate?: Element['animate'] }).animate;
  if (typeof animate !== 'function') return;
  animate.call(el, [{ opacity: 0 }, { opacity: 1 }], { duration: 160, easing: 'ease-out' });
}
```

```js
#!/usr/bin/env node
// Design-brief guard: apps/web may use black, white, grays and exactly one red, and the red
// may only be referenced by the .is-red rule in tokens.css.
//   node scripts/check-colors.mjs            scans apps/web/src and apps/web/index.html
// Exported for tests: findForbiddenColors(files) -> [{ path, line, reason }]
import { readdirSync, readFileSync, statSync } from 'node:fs';
import { join } from 'node:path';

const TOKENS = 'apps/web/src/design/tokens.css';
const ACCENT = '#e3000f';
const NAMED =
  /(?<=[:\s(,])(red|blue|green|yellow|orange|purple|pink|cyan|magenta|teal|navy|brown|lime|olive|maroon|crimson|gold|silver|aqua|fuchsia|violet|indigo|coral|salmon|tomato|orchid|khaki|beige|ivory|tan)(?=[\s;,)!]|$)/i;
const HEX = /#([0-9a-f]{8}|[0-9a-f]{6}|[0-9a-f]{3,4})(?![0-9a-z_-])/gi;

function isGray(hex) {
  const h =
    hex.length === 3 || hex.length === 4
      ? hex
          .slice(0, 3)
          .split('')
          .map((c) => c + c)
          .join('')
      : hex.slice(0, 6);
  return h.slice(0, 2) === h.slice(2, 4) && h.slice(2, 4) === h.slice(4, 6);
}

export function findForbiddenColors(files) {
  const problems = [];
  for (const { path, text } of files) {
    const norm = path.replace(/\\/g, '/');
    const lines = text.split('\n');
    lines.forEach((line, i) => {
      const at = (reason) => problems.push({ path: norm, line: i + 1, reason });
      if (norm.endsWith(TOKENS)) {
        for (const m of line.matchAll(HEX)) {
          const hex = m[1].toLowerCase();
          if (!isGray(hex) && `#${hex}` !== ACCENT) at(`second chromatic color #${hex}`);
        }
        return;
      }
      for (const m of line.matchAll(HEX)) at(`color literal #${m[1]}`);
      for (const fn of ['rgb(', 'rgba(', 'hsl(', 'hsla(', 'color('])
        if (line.includes(fn)) at(`color literal ${fn}`);
      if (/\.css$/.test(norm)) {
        const nm = NAMED.exec(line);
        if (nm) at(`named color ${nm[1]}`);
      }
      if (line.includes('var(--accent)')) at('var(--accent) outside tokens.css');
    });
  }
  return problems;
}

function walk(dir, out = []) {
  for (const name of readdirSync(dir)) {
    const p = join(dir, name);
    if (statSync(p).isDirectory()) walk(p, out);
    else if (/\.(css|ts|tsx|html)$/.test(name) && !/\.test\.tsx?$/.test(name)) out.push(p);
  }
  return out;
}

if (process.argv[1] && /check-colors\.mjs$/.test(process.argv[1].replace(/\\/g, '/'))) {
  const files = [...walk('apps/web/src'), 'apps/web/index.html'].map((p) => ({
    path: p,
    text: readFileSync(p, 'utf8'),
  }));
  const problems = findForbiddenColors(files);
  for (const p of problems) process.stdout.write(`${p.path}:${p.line}: ${p.reason}\n`);
  process.stdout.write(problems.length ? `\n${problems.length} color problem(s)\n` : 'colors ok\n');
  process.exitCode = problems.length ? 1 : 0;
}
```

```ts
import { expect, type Page } from '@playwright/test';

export const ACCENT_RGB = 'rgb(227, 0, 15)';

export interface RedRoot {
  tag: string;
  id: string;
  className: string;
  onsetTick: string | null;
  inSheet: boolean;
}

/** Visible elements whose own computed colors are the accent and whose ancestors are not. */
export function redRoots(page: Page): Promise<RedRoot[]> {
  return page.evaluate((accent) => {
    const out: RedRoot[] = [];
    const props = [
      'color',
      'background-color',
      'border-top-color',
      'border-right-color',
      'border-bottom-color',
      'border-left-color',
      'outline-color',
      'fill',
      'stroke',
    ];
    const walk = (el: Element) => {
      const cs = getComputedStyle(el);
      if (cs.display === 'none' || cs.visibility === 'hidden' || cs.opacity === '0') return;
      if (props.some((p) => cs.getPropertyValue(p) === accent)) {
        out.push({
          tag: el.tagName.toLowerCase(),
          id: el.id,
          className:
            typeof el.className === 'string' ? el.className : (el.getAttribute('class') ?? ''),
          onsetTick: el.getAttribute('data-onset-tick'),
          inSheet: el.closest('.score-sheet') !== null,
        });
        return;
      }
      for (const child of Array.from(el.children)) walk(child);
    };
    walk(document.documentElement);
    return out;
  }, ACCENT_RGB);
}

/** The design brief as a test: one red root, or one playback cursor (note groups sharing an onset). */
export async function expectOneRed(page: Page, label = ''): Promise<RedRoot[]> {
  const roots = await redRoots(page);
  const isCursor =
    roots.length > 0 &&
    roots.every(
      (r) =>
        r.inSheet && r.tag === 'g' && /\b(note|chord)\b/.test(r.className) && r.onsetTick !== null,
    ) &&
    new Set(roots.map((r) => r.onsetTick)).size === 1;
  expect(
    roots.length === 1 || isCursor,
    `${label} expected exactly one red element, got ${JSON.stringify(roots)}`,
  ).toBe(true);
  return roots;
}
```

```ts
  | { id: number; type: 'load'; input: string | Uint8Array; source: string }
  | { id: number; type: 'solve'; score: Score; profile: HandSize; pins?: Assignment }
  | { id: number; type: 'fingeredXml'; xml: string; score: Score; assignment: Assignment };
export type EngineResponse =
  | {
      id: number;
      ok: true;
      type: 'load';
      score: Score;
      editorial: Assignment;
      warnings: string[];
      xml: string;
    }
  | { id: number; ok: true; type: 'solve'; assignment: Assignment; ms: number }
  | { id: number; ok: true; type: 'fingeredXml'; xml: string }
  | { id: number; ok: false; error: string };

// handlers.ts
export function handle(req: EngineRequest): EngineResponse; // never throws; errors become { ok: false }

// client.ts
export interface EngineClient {

    input: string | Uint8Array,
    source: string,
  ): Promise<{ score: Score; editorial: Assignment; warnings: string[]; xml: string }>;
```

```ts
/** A worker that answers from a table, asynchronously, possibly out of order. */
function fakeWorker(
  answer: (req: EngineRequest) => EngineResponse,
  delays: number[] = [],
): WorkerLike & { terminated: boolean } {
  const w: WorkerLike & { terminated: boolean } = {
    onmessage: null,
    terminated: false,
    postMessage(m: unknown) {
      const req = m as EngineRequest;
      const delay = delays.shift() ?? 0;
      setTimeout(() => w.onmessage?.({ data: answer(req) } as MessageEvent), delay);
    },
    terminate() {
      w.terminated = true;
    },
  };
```

```ts
import { injectFingerings, parseMusicXml, solveFingering, unpackMusicXml } from '@digitus2/engine';
import type { EngineRequest, EngineResponse } from './protocol.js';

export function handle(req: EngineRequest): EngineResponse {
  try {
    switch (req.type) {
      case 'load': {
        const xml = unpackMusicXml(req.input);
        const { score, editorial, warnings } = parseMusicXml(xml, { source: req.source });
        return { id: req.id, ok: true, type: 'load', score, editorial, warnings, xml };
      }
      case 'solve': {
        const t0 = performance.now();
        const { assignment } = solveFingering(
          req.score,
          req.pins ? { profile: req.profile, pins: req.pins } : { profile: req.profile },
        );
        return { id: req.id, ok: true, type: 'solve', assignment, ms: performance.now() - t0 };
      }
      case 'fingeredXml':
        return {
          id: req.id,
          ok: true,
          type: 'fingeredXml',
          xml: injectFingerings(req.xml, req.score, req.assignment),
        };
    }
  } catch (e) {
    return { id: req.id, ok: false, error: e instanceof Error ? e.message : String(e) };
  }
}
```

```ts
export type DocStatus = 'idle' | 'loading' | 'fingering' | 'rendering' | 'ready' | 'error';
export interface ScoreDocument {
  status: DocStatus;
  error: string | null;
  score: Score | null;
  xml: string | null; // unpacked source text, without our ids or fingerings
  assignment: Assignment | null; // what is shown: the engine's, or the editorial one when showEditorial
  editorial: Assignment | null; // present when the piece has an editorial fingering (library .fingered file, or <fingering> in a dropped file)
  pages: string[];
  solveMs: number | null;
  renderMs: number | null;
  title: string;
  composer: string;
  warnings: string[];
}
export interface ScoreServices {
  engine: EngineClient;
  renderer: ScoreRenderer;
  fetchText?: (url: string) => Promise<Uint8Array>;
}
export function useScoreDocument(
  source: PieceSource,
  widthPx: number,
  services?: ScoreServices,
): ScoreDocument & { reRender(): void };
export const services: ScoreServices; // module singletons created lazily (one engine worker, one render worker per page)
```

Pipeline, in order: `status = 'loading'`; obtain bytes (library: `fetch(await scoreUrl(path))`; file: the dropped bytes); `engine.load(bytes, name)` → `score`, `editorial`, `xml`; `status = 'fingering'`; `engine.solve(score, settings.handSize)` → `assignment`; `status = 'rendering'`; `fingeredXml = await engine.fingeredXml(xml, score, shown)` where `shown` is the editorial assignment when `settings.showEditorial && editorial has entries`, else the engine's; `renderer.render({ xml: injectNoteIds(fingeredXml, score), widthPx })` → `pages`; `status = 'ready'`. Library pieces with `files.fingered` load the stripped `files.score` for the engine and the `.fingered` file once (lazily, when `showEditorial` is first switched on) to obtain `editorial` through `engine.load` of that file; both files have identical note order, so the editorial assignment is re-keyed by note index onto the stripped score's ids. Any rejection → `status = 'error'` with the message. A change of `handSize` re-solves and patches digits with `setDigits(host, changes, flash)` instead of re-rendering; a change of `showEditorial` or of the width bucket re-renders. Superseded render errors are ignored (not an error state).

Scheduling rules: score time `s` maps to context time `t0 + (s - s0) / tempoFactor` where `(t0, s0)` is the anchor set at `play()` (`t0 = ctx.currentTime + startDelaySec`, default 0.05) and re-set on every tempo change and seek. Each `step()` schedules every note whose onset lies in the half-open window `[horizon_prev, horizon)` with `horizon = (ctx.currentTime + lookAhead - t0) * tempoFactor + s0`; windows never overlap and never leave a gap (the spike's double-trigger bug). Muted hands are skipped at scheduling time. Metronome clicks are scheduled from `buildBeats` in the same windows. Count-in: when `countIn` is on and `play()` starts exactly at a measure start, the anchor moves later by one measure's duration at the current tempo and that measure's beats are clicked (not played). Loop: when a loop `[from, to]` is set, scheduling wraps: score time runs over `[measureStartSec(from), measureEndSec(to))` repeatedly; `positionSec()` returns the wrapped position. At the end of the piece (no loop) the transport stops itself and calls `onEnd`. `pause()` stops the interval, calls `instrument.stopAll()` and freezes `positionSec`. Grace notes are scheduled 50 ms before their principal at a short duration (the engine gives them zero duration).

```ts
export function keyboardRange(score: Score): { lowMidi: number; highMidi: number }; // from the lowest C at or below the lowest note to the B above the highest, at least two octaves
```

Behavior: pressing Play calls `playback.play()`; while playing the Play button becomes `Pause` and is **not** red; the cursor loop (`requestAnimationFrame`) computes `groupIndexAt(groups, playback.positionSec())`, and when the index changes: `clearCurrent(host)`, `setCurrent(host, group.noteIds (minus muted hands), group.tick)`, scrolls the first marked element into view if it is outside the viewport (`scrollIntoView({ block: 'center', behavior: prefersReducedMotion() ? 'auto' : 'smooth' })`, at most once per system change), and sets `pressed` from the group's notes with their fingers from `assignment`. On pause: `clearCurrent(host)`, Play becomes red again, keys released. On end: same as pause, position back to 0. The loop controls (`Loop bars` from/to) call `setLoop` with 0-based measure indices, clamped to the piece. Rewind seeks to 0 (and keeps playing if it was playing).
