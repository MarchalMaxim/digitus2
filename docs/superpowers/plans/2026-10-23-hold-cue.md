# The red waits for the length, and the key fills (issue 185): implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking. Implementers do not run git; the controller commits each task with explicit paths.

**Goal:** While a beginner plays along on their own piano, two things show how long a note lasts.

- The gray bar of each key they hold, on a key a step asked for, rises into a level of the same gray over that note's written length at the Practice tempo. A full key means the note was held long enough.
- The red moves on only when the step has been held for its time: the gap to the next step, never longer than the step's shortest note.
- A release that comes too early leaves the red where it is, and the status line says `Hold the red note a little longer.`

Nothing changes outside play-along: with no piano, during Play, while loading and in print.

## Rulings (fixed; do not re-open)

Settled against the code. A builder who finds one wrong stops and reports.

1. **A step runs** while every pitch of it is held and fresh. Its run starts at the latest press time among its pitches (`runSince`). That moment has one name in the pure module and one commented site in the hook, separate from the pass, so that issue 184's accompaniment can hang on it.
2. **A step's hold**, in performance seconds, is computed by `holdSec(steps, times, index, loop)`:
   - `min(gap, shortestSec)`, and never below 0;
   - `gap` is the next step's `perfSec` minus this step's;
   - for the piece's last step, `gap` is `Infinity`, so the hold is its shortest note;
   - inside a loop, for the loop's last step, `gap` is `loop.to - perfSec`. This is the time the note sounds before Play would loop back, which is what the gap to the next onset means everywhere else. The same cap on the shortest note applies, so a rest before the loop's end is not waited out.
   - `shortestSec` is the minimum of `offsetSec - onsetSec` over every non-grace note of the played hands starting at that tick, both voices and both hands of a unison included.
   - In real milliseconds, the hold is `holdSec * 1000 / factor`.
3. **A key's length** for its level is the longest `offsetSec - onsetSec` among the step's notes at that required pitch. Two voices in unison with different lengths take the longer one. An ornamented note gives its required pitch (the upper neighbour of an upper-start trill) the principal note's length.
   - Ties are one engine `Note` (`sourceIndices`), so a tied note counts whole.
   - `performanceOf` clips a note's `offsetSec` at its run's end (`Math.min(n.offsetSec + ds, runEndSec[p])` in `audio/performance.ts`). So a tie across a repeat's end counts up to that end, and the hold and the level use the clipped length. This is the behaviour, documented in `docs/app.md`; the tie test keeps its tie inside one run.
4. **When a step passes** (`settle`):
   - **On its time.** A running step passes when `now - runSince >= holdMs` (1e-6 ms slack).
   - **On a release.** On a release of one of its pitches, it passes if `now - runSince >= HOLD_TOLERANCE * holdMs`. The pass happens before the key is removed, at the release.
   - **An earlier release** of one of its pitches:
     - removes that key;
     - leaves the other keys fresh;
     - leaves the red where it is;
     - sets `early`.

     A fresh press of the released key restarts the run from that press, because `runSince` is the latest press.

   - **Chains.** After a pass, the next step (in walk order, wrapping in the loop) is checked at the same `now` against its own `runSince`. A key pressed early for it counts from its own press. A chain therefore covers exactly the steps whose elapsed time is up.
   - **The bound.** At most `steps.length` passes. One `cueAt` (or `finish`) goes to where the chain ends, as today.
5. **No pass while a flight or hop is on screen**, as today: `decide` returns before the settle.
   - Presses are still recorded with their times. When the red lands, the align (already a dependency on `flightShown`) settles at the landing's `now`.
   - A release during a flight is a plain release, with no pass and no `early`. The flight is the app's move, not the reader's, so it shows no hint.
6. **The wake-up timer.** After every `decide` that leaves a running step behind, one `setTimeout` is set for `wakeAtMs - now`, where `wakeAtMs` is `runSince + holdMs` of the step the red waits on. It calls `decide(null)`.
   - Every `decide` clears it before it sets it again.
   - Unmount, `!active`, and the walk becoming inactive clear it.

   Late firing is harmless: the settle reads `performance.now()`.

7. **The early flag** (`early`, for the status line):
   - **Set** by an early release (ruling 4).
   - **Cleared** by any pass, an external move (`moved`), and the walk going inactive.
   - **Mirrored in a ref:** `setEarly` is called only on a change, so a release that changes nothing re-renders nothing.
8. **Levels: which keys, and from when.** After every `decide` that reaches the settle, the hook gives a level to each pitch held and fresh that has none. The pitch must belong to the step the red waits on (`to`), or to the step after it in walk order (an early press). The level counts from that key's own press time, with that step's length and beat count for the pitch. So a level is assigned:
   - at the press, for a key of the current step or of the next step;
   - when the red arrives, for a key already held for the new step.

   A key keeps its level until it is released, so a left-hand whole note held under the melody keeps filling after the red moves on.
   - **No level** goes to a wrong note, a pitch of the hand left out, or a key held but spent.
   - **During a flight** the settle is not reached, so a press gets its level when the red lands. The level is counted from the press, so it appears at the right height.

9. **Levels: going.**
   - **A release** of a key whose level is below 1 drains it from the level reached to nothing over `--dur-slow`, read from computed style. Under reduced motion that is 0 ms, so the drain is instant without a branch of its own.
   - **A release of a full key** removes its level with its bar.
   - **An external move** (`moved`: the keys are spent) clears every level at once.
   - **The walk going inactive** clears every level at once. That covers Play, loading, the piano going, a new layout and unmount.

   So no level is ever drawn while the transport plays, while loading or without a piano.

10. **The beat, under reduced motion.**
    - **Which beat.** The beat is the time signature's beat: `divisions * 4 / beatType` ticks, from the time signature in force at the step's tick on the performance score. That is exactly the beat `buildBeats` in `audio/beats.ts` gives the metronome and the count-in, so the level steps on the clicks a beginner hears and counts. A quarter note would disagree with the metronome in 6/8 (eighths), 2/2 (halves) and 3/8.
    - **What follows.** 6/8 steps in eighths and 2/2 in halves.
    - **The steps.** Each key's note is `beats = noteTicks / beatTicks` beats long. Its level is `floor(f * beats + 1e-9) / beats`, where `f` is the fraction of its real length elapsed. A note of one beat or less (`beats <= 1`) shows 0 until `f >= 1`, then 1.
    - Being a fraction of the real length, the stepping needs no tempo, and a tempo change in the middle of a note cannot desynchronise it.
11. **The level's geometry**, in the keyboard's units. These are from the mock-up and from `heldBar` in `Keyboard.tsx`:
    - The bar is `x = k.x + inset`, `width = w - 2 * inset`, `rx = 1`. The inset is 3 on a white key and 2 on a black one. The bar's `y` is `h - 8` (white) or `h - 6` (black), and its height is 5 or 4.
    - The level's bottom is the bar's bottom: `bottom = bar.y + bar.height`, which is 97 on a white key and 60 on a black one.
    - The level's height at `level > 0` is `bar.height + (bottom - inset - bar.height) * level`, with the top inset 3 on a white key and 2 on a black one. Its `y` is `bottom - height`. At `level = 0` the height is 0.
    - Full, that is `y = 3` and `height = 94` on a white key, and `y = 2` and `height = 58` on a black one.
    - It has the bar's `x`, `width` and `rx`.
12. **The level's colour, and the text on it.**
    - **On a key that shows its state** (pressed, white or black), and on a white key that is not pressed: `--key-held`. These are the bar's own pairs, 3.6:1 and 3.4:1 against `--key-down`, and 5.7:1 and 7.8:1 against `--key-white`.
    - **On a black key that is neither pressed nor dimmed** (an early press, or a key held past its note): `--key-held-on-black`, class `is-on-black`, exactly as its bar. Its pair is 3.7:1 and 3.3:1 against `--key-black`. `--key-held` there would be about 1.6:1 in dark. Such a key shows no text, because a black key shows a number only when pressed or dimmed, so it needs no clipped copy.
    - **A dimmed key** (`.is-muted`) never draws a level, even if the store has one. That case cannot arise from the hook, but the keyboard guards it.
    - **Where the level covers the finger number:** the number is drawn again, after the original, as `text.key-on-level`, in `--key-on-level`, clipped to the level. `--key-on-level` against `--key-held` is 5.7:1 in light and 7.7:1 in dark, at least 4.5:1 for text. The original number stays first in the key's group, so `querySelector('text')` still finds it (`Keyboard.test.tsx`, `e2e/keyboard.spec.ts`).
    - **The hand letter** gets a copy too, `text.key-hand-on-level`, which is not of class `key-hand`, so the `.key-hand` counts stay as they are.
    - **Copies exist only while the key has a level.** They are `aria-hidden` and ignore the pointer.
13. **Clip spaces.**
    - The level and the number's copy sit in the key's group, which takes the key-travel `scaleY` (base.css). Their clip path is defined inside the group too, so it shares the transform.
    - The hand letters are a layer of their own, which is not transformed. The letter's copy sits in that layer with its own clip path, whose rect is the level's rect mapped through the key's pressed scale: `y * s` and `height * s`, with `s = KEY_TRAVEL.white` (0.976) or `KEY_TRAVEL.black` (0.96). Hand letters show only on pressed keys (dimmed keys have no level), so `s` is always the pressed scale.
    - `KEY_TRAVEL` is exported from `Keyboard.tsx`. `Keyboard.test.tsx` reads `base.css` and checks that it matches the two `scaleY` values. The copy is exact at rest and off by under a unit only during the 50 ms press.
    - Clip path ids come from `useId()`, stripped to `[A-Za-z0-9_-]`, plus the midi number.
14. **The status line.**
    - The hook's `hint` becomes `AlongHint | null`, where `AlongHint = { kind: 'play' | 'hold'; count: number }`.
    - `hold` shows while `early` is set and the red is cued at its step (`cuedHere`). `play` shows as today, while `played === 0` and cued here.
    - `hold` wins over `play`, because it is the more specific advice.
    - Both are the lowest line in `scoreStatusLine`.
    - `count` is the step's pitch count, so the line says `notes` for a step of several pitches.
15. **The test hook** (`?audio=silent` only) gains a read-only `hold(): number`, the hold in real milliseconds of the step `target()` names, 0 when none. It is not a shortcut; it only reports.

```ts
/** A release after this fraction of a step's hold passes the step at the release (issue 185). */
export const HOLD_TOLERANCE = 0.8;

/** The times of one step (issue 185), aligned with `alongSteps`' steps. Performance seconds. */
export interface StepTime {
  /** The shortest non-grace note of the hands played starting at the step's tick. */
  shortestSec: number;
  /** The longest note at each of the step's pitches, aligned with `AlongStep.pitches`. */
  lengthSec: readonly number[];
  /** Each of those notes' length in beats of the time signature in force (rulings 3 and 10). */
  beats: readonly number[];
}

/**
 * The steps and their times: `steps` is exactly `alongSteps(perf, mutedHands)`, built in the
 * same pass; `times[i]` belongs to `steps[i]`.
 */
export function alongPlan(
  perf: Performance,
  mutedHands: readonly Hand[],
): { steps: AlongStep[]; times: StepTime[] };

/** The step's hold in performance seconds (ruling 2). */
export function holdSec(
  steps: readonly AlongStep[],
  times: readonly StepTime[],
  index: number,
  loop: PerfRange | null,
): number;

/** The step after `index` in walk order: the loop's first after its last; -1 after the piece's last. */
export function stepAfter(
  steps: readonly AlongStep[],
  index: number,
  loop: PerfRange | null,
): number;

/** The press time (performance.now ms) of each key held now. */
export type Presses = ReadonlyMap<number, number>;
export const NO_PRESSES: Presses;
export function pressAt(presses: Presses, midi: number, atMs: number): Presses;
export function liftAt(presses: Presses, midi: number): Presses;

/**
 * When the step starts running (ruling 1): every pitch held and fresh, the latest press among
 * them; null while it does not run. Issue 184's accompaniment starts here.
 */
export function runSince(step: AlongStep, keys: Keys, presses: Presses): number | null;

export interface SettleInput {
  steps: readonly AlongStep[];
  times: readonly StepTime[];
  index: number;
  keys: Keys;
  presses: Presses;
  loop: PerfRange | null;
  nowMs: number;
  /** The tempo factor: real seconds = performance seconds / factor. */
  factor: number;
  /** A key coming up now (ruling 4): judged against the running step before it is removed. */
  releasing?: number;
}

export interface Settled {
  keys: Keys;
  presses: Presses;
  move: AlongMove;
  passed: number;
  /** A release of the running step's pitch before HOLD_TOLERANCE of its hold. */
  early: boolean;
  /** The step the red is on after the settle (the cue's index; `index` when it stays; -1 on finish). */
  at: number;
  /** When the step at `at` is due (runSince + hold), null when it does not run. */
  wakeAtMs: number | null;
  /** The step at `at` running: its index and since when (ruling 1), else null. */
  run: { index: number; sinceMs: number } | null;
}

/** The timed rule (rulings 2 to 4). `releasing` is removed from keys and presses in the result. */
export function settle(input: SettleInput): Settled;
```

### 1.3 `apps/web/src/score/keyLevels.ts` (new, pure apart from the store's one timer)

```ts
/** One key's level (issue 185). Times are performance.now ms; lengths real ms at the tempo. */
export interface KeyLevel {
  atMs: number;
  lengthMs: number;
  /** The note's length in beats (ruling 10). */
  beats: number;
  /** Set when the key was let go before full: the drain starts here, from `fromLevel`. */
  upMs: number | null;
  fromLevel: number;
  drainMs: number;
}
export type KeyLevels = ReadonlyMap<number, KeyLevel>;
export const NO_LEVELS: KeyLevels;

/** 0..1 at `nowMs` (rulings 9 and 10). */
export function levelAt(l: KeyLevel, nowMs: number, reduced: boolean): number;

/** Whether the level still changes after `nowMs` (rising below 1, or draining). */
export function moving(l: KeyLevel, nowMs: number, reduced: boolean): boolean;

/** The level's rectangle for a key (ruling 11): the bar's x, width and rx; y and height from `level`. */
export function levelRect(
  black: boolean,
  bar: { x: number; y: number; width: number; height: number },
  level: number,
): { x: number; y: number; width: number; height: number; rx: number };

export interface LevelStore {
  subscribe(listener: () => void): () => void;
  /** The same map until a level is added, released or removed. */
  get(): KeyLevels;
  /** A key's level starts (or starts again, replacing a drain). */
  start(midi: number, level: Omit<KeyLevel, 'upMs' | 'fromLevel' | 'drainMs'>): void;
  /** The key is let go at `nowMs`: drains from where it is, or goes now when full or drainMs is 0. */
  release(midi: number, nowMs: number): void;
  /** Every level goes at once (an external move, the walk inactive). */
  clear(): void;
  /** Cancels the drain timers (unmount). */
  dispose(): void;
}

/** `drainMs` defaults to the `--dur-slow` token (`durationMs` in design/motion.ts). */
export function createLevelStore(o?: {
  drainMs?: () => number;
  reduced?: () => boolean;
}): LevelStore;
```

`release` computes `fromLevel = levelAt(l, nowMs, reduced())`:

- When `fromLevel >= 1`, `fromLevel <= 0` or `drainMs() === 0`, it deletes the key's level.
- Otherwise it sets `upMs`, `fromLevel` and `drainMs`, and a `setTimeout` deletes the level after `drainMs`.

A `start` for the same key cancels that timer. Every change hands out a new `Map` and notifies.

  5. **A release:**

     - Otherwise, keep the key in `keysRef` for the settle, which removes it (`releasing`), and call `levels.release(midi, now)`.

     The early `return` on a note-off that the code has today goes. Every exit of `decide` before the settle (the flight, `homeRef`, `pb.playingNow()`, the anchor finding no step, `here < 0`) first removes the releasing key from `keysRef` and `pressesRef` and calls `levels.release`. A released key never stays held.
     - `setIndex` is called only when `indexRef` changes, like `setEarly`. A note that moves nothing then schedules no render of the score view: React can render a component once before it bails out of an equal update.

  6. **The settle.** After the anchor, call `settle({ …, index: here, nowMs: now, factor, releasing })`. Write back `keysRef` and `pressesRef`.
